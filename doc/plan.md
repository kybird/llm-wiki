# llm-wiki 재출발 계획

> 2026-08-12 세션 정리. 이 문서가 현재 결정의 SSOT다.

## 0. 전제 — 이 레포가 베이스다

`D:\Project\kybird-nest`(TypeScript, 3.2만 줄, 칸반·웹UI·싱크·멤버십 구현됨)는
**참고용으로만** 둔다. 코드를 읽을 가치는 있지만 개발은 여기서 한다.

되돌아온 이유: kybird-nest는 "서버가 정본"을 **위키에까지** 적용했다. 그래서
에이전트가 지식을 보려면 `CLI 설치 → link → repo join → 서버 기동 → embed 실행`
사슬이 필요하고, 고리 하나만 빠지면 그 에이전트는 다른 컨텍스트를 본다.
지식이 레포의 md 파일이면 이 문제가 존재하지 않는다 — `git clone`이면 끝.

### 데이터 성질별 저장소

| 데이터 | 성질 | 저장소 |
|---|---|---|
| 위키 텍스트 | 추가 위주, 사람이 읽음, 병합 가능 | **레포의 md + git** |
| 임베딩/검색색인 | md에서 유도 가능한 캐시 | 로컬, gitignore, 동기화 안 함 |
| 칸반 카드 상태 | 순서 있는 가변 상태 | git으로 병합 안 됨 → 미결 |

## 1. 최종 목표

**사람은 기획 루프만 돌고, 밤새 무인으로 코딩이 도는 시스템.**
Z.AI 오프피크 요금이 근거라 사람 승인을 루프 안에 두면 안 된다.

### 성립 조건과 현재 상태

| 조건 | 왜 필요한가 | 지금 |
|---|---|---|
| 작업이 프로세스 밖에 | 세션이 죽어도 다음이 이어받음 | 없음 |
| 상태 갱신이 **보장** | 안 하면 다음 세션이 뭘 할지 모름 | 없음 |
| 막혀도 안 멈춤 | 카드 하나가 밤을 통째로 먹으면 안 됨 | 없음 |
| 기억 | 밤새 같은 실수 반복 방지 | **위키 — 유일하게 있는 것** |
| 검증(QA) | 아침에 사람이 전부 안 봐도 되게 | 없음 |
| 승인 없이 진행 | 승인 대기 = 오프피크 낭비 | 없음 |

**진짜 병목은 검증이다.** 밤새 카드 10개를 처리했는데 아침에 10개를 다
리뷰해야 하면 절약이 0이다. 무인 루프의 가치는 "밤에 돌았다"가 아니라
**아침에 안 봐도 되는 비율**에서 나온다. 그러려면 카드가 검증 가능한 형태로
쓰여야 하고, 그게 기획 루프가 실제로 하는 일이다.

## 2. 즉시 할 일 — 검색 신뢰도 복구

증상: 위키에 있는 지식을 검색이 자주 못 찾는다.

### 2.1 [최우선] 시맨틱이 결과를 내면 grep이 아예 안 돈다

`lib/wiki-search.js:45` — `qmdSucceeded`가 true면 grep fallback을 건너뛴다.
QMD가 유사도로 엉뚱한 문서 **하나만** 물어와도 "성공"으로 치고, 그 단어가
정확히 박혀있는 문서를 못 찾는다.

**이건 색인 상태와 무관하게 돈다. 그리고 색인을 갱신할수록 나빠진다:**

- 색인이 낡음 → QMD 빈 결과 → grep 돎 → 정확 매칭은 나온다
- 색인이 싱싱함 → QMD가 거의 모든 질의에 뭐라도 물어옴 → grep 영영 안 돎

즉 `compile index`를 성실히 돌릴수록 재현율이 떨어진다.

**고침:** fallback이 아니라 **항상 둘 다 돌려서 합친다.** 시맨틱은 표현이
달라도 잡고, grep은 정확한 문자열을 잡는다 — 대체재가 아니라 보완재다.

> ⚠️ 이걸 고치기 전에는 어떤 측정도 의미가 없다. 전부 이 버그에 오염된 숫자다.

### 2.2 grep에 순위가 없고 매칭 줄을 안 보여준다

`lib/wiki-search.js:76` — 키워드마다 따로 돌려 Set에 합친다. 5개 중 5개 맞는
문서와 1개만 맞는 문서가 같이 나오고, **파일명만 출력**해서 에이전트가 어느
걸 열어야 할지 모른다.

**고침:** 매칭 키워드 수로 정렬 + 매칭된 줄 같이 출력.

### 2.3 쓸 때와 찾을 때 어휘가 다르다

`skills/wiki-log/SKILL.md:31`의 "Concept Drift Protection"은 *기존 이름을
재사용하라*는 것뿐이고 별칭 요구가 없다.

**고침:**
- frontmatter에 `aliases: [세션 끊김, token expired, 401 대신 500]` 강제
- **에러 메시지 원문 보존.** 실무 검색어는 보통 에러 메시지 붙여넣기인데,
  raw의 `### Error` 원문이 compile되며 요약되면 걸릴 문자열이 사라진다

### 2.4 `compile index`를 아무도 안 부른다

CLI에만 있고 어디서도 호출되지 않는다. pre-commit 훅은 CLAUDE.md 미러링만
한다. README의 "Periodically: use wiki-compile"이 유일한 트리거 — 즉 사람이
기억해야 돈다. 2.1을 고친 뒤에야 색인 갱신이 이득이 된다.

**순서: 2.1 → `compile index` → 재측정 → 2.2 / 2.3**

## 3. 칸반 — 미결

### 3.1 확정된 것

**지시로는 안 된다.** 에이전트는 시스템프롬프트에 박힌 todo(TodoWrite류)를
프로젝트 스킬보다 우선하고, 그 todo는 세션과 함께 사라진다. 이게 파편화
(`plan.md`/`done.md`/`todo.md`가 생기고 결국 `plan.md`만 남는 현상)의 실제
출처다. 스킬로 "board.md를 써라"라고 해봐야 진다.

**그래서 방향은 캡처다.** 에이전트에게 보드를 쓰라고 하지 않는다. 네이티브
todo를 그대로 쓰게 두고, **훅으로 낚아채서 파일에 쓴다.** 에이전트는 보드
파일의 존재를 몰라도 된다 — 지시도 준수 문제도 없다.

캡처 지점은 하네스마다 다르다:

| | 커버 범위 | 이식성 |
|---|---|---|
| git 훅 | 커밋 시점만 | 모든 도구 ✅ |
| 하네스 훅 (Claude Code settings.json 등) | 세션 생명주기 전체 | 도구마다 제각각 |
| 하네스를 소유 (Pi 익스텐션) | 전부 | 그 하네스에서만 |

**다음 확인:** Claude Code에서 TodoWrite를 실제로 가로챌 수 있는가. 되면
코드 없이 검증 가능하다.

### 3.2 아직 안 정한 것

- **저장 형태.** 파일 하나(섹션으로 상태 구분) / 카드당 파일 / 서버
- **정본이 무엇인가.** 파일 포맷이 스펙인가, 아니면 llm-wiki 기존 패턴대로
  스킬이 본체이고 파일은 그 결과인가
- 카드 고유번호는 **안 쓴다** — 제목이 곧 식별자(위키 `[[제목]]`과 동일 규칙)
- 완료 카드 아카이브 정책

### 3.3 설계 원칙 (합의된 것)

- **한 작업의 상태와 내용이 다른 파일에 있으면 한쪽은 반드시 썩는다.**
  `plan.md`/`todo.md`/`done.md`가 죽은 이유이고, "보드 표 + 카드 본문 파일"
  분할안이 기각된 이유다.
- **생성물은 갱신을 강제하는 게 없으면 썩는다.** `index.md`가 산 증거다.
  그래서 "보드는 생성된 인덱스로 두자"는 안 된다.
- **에이전트는 파일 하나를 읽는다.** 보드 전체를 보려고 파일 N개를 읽거나
  CLI를 호출해야 하면, 그건 서버를 버린 이유와 같은 종류의 의존성이다.

### 3.4 장기

기획 / 개발 / QA 3보드. 기획 완료 → 개발 투입, 개발 완료 → QA, QA 반려 →
개발이나 기획으로 되돌림. 기각 경로가 순환을 닫는다.

## 4. 스킬 · 시스템프롬프트 배포

### 4.1 서버는 필요 없다

`llm-wiki init`이 이미 패키지의 `skills/`를 `.agents/skills/`와
`.claude/skills/`로 복사한다. 층은 셋:

1. **패키지 스킬** — 모든 레포 공통
2. **레포 스킬** — `.agents/skills/`, git 커밋, 동료와 공유
3. **개인 오버라이드** — `*.local.md`, gitignore

갱신 규칙: **사용자가 손댄 파일은 덮어쓰지 않는다.** 파일 맨 위 마커 줄이
사라졌으면 손댄 걸로 보고 건너뛴다.

### 4.2 배포는 npm이 아니라 git

프롬프트 오타 하나 고치려고 버전 올려 publish할 수 없다. 안 고치게 되고,
안 고치면 스킬이 썩는다.

```
llm-wiki skills add <git-url>    스킬 레포 등록
llm-wiki skills sync             pull 받아 이 레포에 설치
```

활성 목록은 이미 있는 `llm-wiki.config.json`에 둔다:

```json
{ "skills": { "sources": ["..."], "enabled": ["wiki-search", "kanban"] } }
```

이 파일이 git에 커밋되므로 새 컴퓨터·동료 모두 같은 세트를 받는다.

**받은 스킬은 레포에 복사한다**(참조 아님). 레포가 자기 완결적이어야
`clone` 한 번으로 끝나고, 참조만 하면 `sync` 안 친 사람이 다른 스킬로 일한다.

### 4.3 외부에서 받는 건 스킬만

스킬은 독립 파일이라 소스가 열 개여도 나열만 하면 된다 — 충돌 없음.
시스템프롬프트 조각은 **합성**이 필요해서 순서·우선순위·충돌 해결이 붙고,
산문 지시의 충돌은 도구가 못 잡는다("한국어로 답해라" vs "always in English").

그래서 `AGENTS.md`는 각 레포가 직접 쓰는 짧은 파일로 두고, 합성 배관을 안
만든다. 기존 pre-commit 훅(CLAUDE.md 정본 + 미러 강제)도 손댈 게 없다.

### 4.4 AGENTS.md에 무엇을 두는가

| | AGENTS.md | 스킬 |
|---|---|---|
| 로드 | 매 세션, 항상 | 관련될 때만 |
| 비용 | 모든 세션의 컨텍스트를 영구히 | 목록에 한 줄 |
| 여러 소스 | 합쳐야 함 → 충돌 | 나열 → 충돌 없음 |

**기준: 에이전트가 "찾아볼 생각"을 하기 전에 알아야 하는 것만 AGENTS.md.**

### 4.5 남의 레포를 받을 때

남의 스킬을 sync하는 건 **그 사람이 쓴 지시를 내 에이전트가 따르게 하는
것**이다. 코드가 아니라 지시라서 리뷰 없이 들어오면 알아채기 어렵다.
`sync`는 자동이 아니라 명시적으로 치는 명령이어야 하고, diff를 보여주고
승인받아야 한다.

## 6. 조사한 기존 솔루션

**Nimbalyst** (MIT, Electron, 로컬 우선) — 카드가 마크다운 + frontmatter,
git 동기화, 칸반. 전용 폴더 `nimbalyst-local/tracker/`만 스캔하고 파일 안에서
`#type[...]` 태그 또는 `trackerStatus` frontmatter로 항목을 표시한다.

**하지만 todo 캡처를 안 푼다** — 에이전트에게 "워크스페이스의 태스크 파일을
읽고 갱신하라"고 지시하는 층에 머문다. 위키/지식 레이어도 없고, 팀 실시간
동기화는 closed-source 서버다.

vibe-kanban / ai-agent-board / openkanban / saltbo-agent-kanban — 전부
"카드 하나 = worktree 하나 = 에이전트 세션 하나" 오케스트레이터다.

**공통점: 아무도 지식 레이어와 3루프 승계를 안 한다. 그리고 아무도 todo
캡처를 안 푼다.** 후자가 실제 차별점이다.

**Pi** (earendil-works/pi, MIT, TypeScript, ~54k★) — 익스텐션이 TS 모듈이고
tools/슬래시명령/단축키/**이벤트**/TUI 전체에 접근한다. 시스템프롬프트가
1000토큰 미만 + lazy skills. **포크가 아니라 익스텐션으로 붙인다** — 포크하면
빠르게 움직이는 업스트림을 평생 따라가야 한다.

파일이 바닥이면 어떤 에이전트든 그냥 읽는다. Pi 익스텐션은 그 위에 얹는
**강제 층**이다. 반대로 Pi 안에만 상태를 두면 다른 도구에서 아무것도 안 보인다
— kybird-nest에서 서버로 했던 실수의 재판이다.

## 7. 이 세션에서 얻은 교훈

- **배관을 먼저 깔지 마라.** kybird-nest가 실패로 느껴진 원인은 코드 품질이
  아니라, 만들어진 배관이 전부 **오지 않은 소비자**를 향해 있었다는 것이다.
- **SSOT 맨 앞에 목적지를 두면 읽는 사람이 현재를 목적지의 렌즈로 오독한다.**
  kybird-nest `brief.md` 0장이 그랬고, 이번 세션에서 마이그레이션 도구
  (`backfill`)를 무인 루프 인프라로 오독하는 사고가 실제로 났다. 목적지는
  유효하되 현재 구현과 분리해서 적어야 한다.
