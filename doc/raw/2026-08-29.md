## Case 1: MSVC + CUDA Toolkit 버전 불일치로 node-llama-cpp 소스빌드가 STL1002로 죽는다

### Grounding
- Evidence: TROUBLESHOOTING.md ("MSVC / CUDA Toolkit version matrix")
- Confidence: 5/5

### Error
error STL1002: Unexpected compiler version, expected CUDA 12.4+

### Environment Context
- Packages: @tobilu/qmd (node-llama-cpp v3.x), Windows + NVIDIA
- Migration Issue: Yes (VS 2022 자동 업데이트가 MSVC를 밀어올림)

### Fix Code
CUDA Toolkit을 MSVC 요구치에 맞춰 업그레이드. MSVC 14.44+는 CUDA 12.4+ 필수.
(14.39 이하는 CUDA 11.x 허용, 14.40–14.43은 12.0+ 권장)

### Analysis
- Root cause: MSVC의 yvals_core.h 정적 단언이 컴파일 시점에 최소 CUDA 버전을 강제한다.
- Why it failed: VS 2022 자동 업데이트가 MSVC를 올리면 CUDA Toolkit을 같이 안 올린
  빌드에서 호환성 위반이 난다. GPU 하드웨어/드라이버 상태와는 무관.
- How it was fixed: prebuilt 바이너리 경로를 살려 소스빌드 자체를 안 가게 한다 —
  CUDA 버전을 하나만 설치하면 win-x64-cuda prebuilt가 깨끗히 로드된다.

### Related Knowledge
- Patterns: [[node-llama-cpp-prebuilt-resolution]]
- **Anti-Patterns**: [[CUDA-version-coexistence]]

## Case 2: 런타임 CUDA OOM은 드라이버/VRAM 상태 문제다 — 빌드 실패와 다르다

### Grounding
- Evidence: TROUBLESHOOTING.md
- Confidence: 4/5

### Error
CUDA error: out of memory

### Environment Context
- Packages: @tobilu/qmd (node-llama-cpp v3.x)
- Migration Issue: No

### Fix Code
해당 실행에 한해 `QMD_LLAMA_GPU=false`로 CPU 강제.

### Analysis
- Root cause: 일시적 드라이버/VRAM 상태 (GPU 절전 등). 빌드 실패와 전혀 다른 모드.
- Why it failed: 변수명 착각이 흔하다 — `NODE_LLAMA_CPP_GPU`는 qmd 코드베이스가
  읽지 않는다. 아무 효과 없는 이름.
- How it was fixed: `QMD_LLAMA_GPU`만 유효하다.

## Case 3: QMD 컬렉션 이름 충돌 — 에러 없이 다른 프로젝트 로그가 뒤섞인다

### Grounding
- Evidence: lib/find-doc-root.js 주석 (2026-07-25 실제 발생)
- Confidence: 5/5

### Discovery
두 프로젝트가 기본 컬렉션 이름을 그대로 쓰면 전역 QMD 설정(~/.config/qmd/index.yml)에서
이름이 충돌해, 서로의 raw 로그가 검색에 뒤섞인다. 증상이 조용하다 — 에러 없이
"0 new"만 찍히고 엉뚱한 프로젝트 결과가 나온다.

### Analysis
- Why non-obvious: 검색이 "성공"으로 보이므로 오염을 알아채기 어렵다.
- Impact: 모든 검색 측정을 오염시킨다. 조용한 실패의 전형.
- Action taken: 기본 컬렉션 이름을 리포 폴더명 기반으로 생성(llm-wiki-wiki /
  llm-wiki-wiki-raw) + init 시점 충돌 경고.

### Related Knowledge
- Concepts: [[qmd-optional-dependency]]
- **Anti-Patterns**: [[shared-default-collection-names]]

## Case 4: compile list 판정을 mtime 대신 로그 헤더 날짜로 한다

### Grounding
- Git Context: `hash:fd01a03`
- Confidence: 5/5

### Design Decision
`llm-wiki compile list`의 "새 로그" 판정을 파일 mtime이 아니라 로그 헤더의
`# YYYY-MM-DD` 날짜로 한다. 헤더가 없는 파일만 mtime으로 폴백.

### Alternatives Considered
- Option A: mtime 유지 — git checkout이 머신마다 mtime을 갈려 중복/누락이 생김. 기각.
- Option B: git 인덱스 추적 — 복잡도 대비 이득 없음. 기각.
- Selected: 헤더 날짜. ISO 날짜 문자열 비교는 달력 순서와 일치하므로 정렬도 공짜다.

### Analysis
- Context: 같은 날 컴파일해도 mtime이 남아 same-day 오탐이 계속됐다.
- **Trade-offs**: 헤더 날짜는 로그 작성 규칙(`# YYYY-MM-DD`)에 의존 — 규칙이 깨지면
  mtime 폴백이 받는다.
- Reversibility: High

### Related Knowledge
- Patterns: [[header-date-over-mtime]]

## Case 6: QMD 시맨틱이 "성공"하면 grep이 건너뛰어 정확 매칭이 묻힌다

### Grounding
- Git Context: `hash:b795e4e`
- Evidence: lib/wiki-search.js, improvement-plan.md 0단계
- Confidence: 5/5

### Error
위키에 확실히 있는 지식을 실제 에러 메시지 문자열로 검색해도 못 찾는다. 색인을 갱신할수록 더 못 찾는다 — compile index를 성실히 돌릴수록 재현율이 떨어지는 역설.

### Environment Context
- Packages: @tobilu/qmd (optional semantic search)
- Migration Issue: No

### Fix Code
`qmdSucceeded` 분기 제거 — QMD 결과와 grep 결과를 항상 둘 다 출력한다(grep 먼저).
grep은 매칭 키워드 수 내림차순 정렬 + 매칭 줄 스니펫.

### Analysis
- Root cause: 유사도 검색이 뭐라도 하나 반환하면 "성공"으로 치고 grep fallback을 건너뛴 구조 (plan.md 5.1(1)).
- Why it failed: 시맨틱을 grep의 대체재로 봤다 — 보완재다. 시맨틱은 표현이 달라도 잡고, grep은 정확한 문자열을 잡는다.
- How it was fixed: 가짜 qmd CLI(QMD_CLI_PATH)로 병합 분기 검증 + 이 레포 doc/raw로
  'Unexpected compiler version, expected CUDA 12.4+' 실측 — 6/6 키워드 1위.

- Concepts: [[qmd-optional-dependency]]
- Patterns: [[always-merge-exact-matching]]

## Case 7: 칸반 저장 형태 — 카드당 파일 + board는 유도 뷰 (미결 #1 해소)

### Grounding
- Git Context: `hash:d400429`
- Evidence: lib/kanban.js, lib/kanban-cmd.js
- Confidence: 4/5

### Design Decision
plan.md 미결 #1(칸반 저장 형태)을 카드당 파일로 해소. 상태(frontmatter)와 내용(본문)이
같은 파일에 있고, 종결(done/superseded/abandoned)은 폴더가 말한다. board 뷰는 유도물.

### Alternatives Considered
- Option A: 보드 표 + 카드 본문 분할 — 상태와 내용이 갈라져 한쪽이 반드시 썩는다(3.7 원칙 1). 기각.
- Option B: board를 생성 인덱스로 — 갱신을 강제하는 게 없으면 썩는다(원칙 2, index.md가 산 증거). 기각.
- Option C: 서버 — 파일이 정본으로 돌아온 이유와 정면충돌. 기각.
- Selected: 카드당 파일. Backlog.md·kanban-md가 같은 구조의 존재 증명이고, pick이
  카드 한 경로만 주므로 "에이전트가 N개를 읽는다"는 반례도 해소된다.

### Analysis
- Context: 카드 쓰기는 CLI만 — 사람 손편집 round-trip을 처음부터 포기해 1,250줄 파서의
  원인을 제거. 섹션 경계는 센티넬 주석으로.
- **Trade-offs**: 파일명에 제목 포함(이름 변경 리스크) — 제목=식별자(3.5 확정)가 먼저고,
  카드는 폐기·대체로 끝나 이름 변경 빈도가 태스크 트래커보다 낮다. 변경은 supersede로.
- Reversibility: High — 포맷이 md+frontmatter뿐이라 파서는 100줄대.

### Related Knowledge
- Patterns: [[always-merge-exact-matching]]
