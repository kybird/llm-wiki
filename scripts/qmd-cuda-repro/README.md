# qmd 리랭커 CUDA 가짜 OOM — 소거 행렬 하네스

마일스톤 **qmd 리랭커 CUDA 가짜 OOM 근본 수리**의 카드 1 산출물.
win32 CUDA에서 리랭크(`rankAll`)가 여유 VRAM에서도 가짜 OOM으로 프로세스째
크래시하는 상류 결함의 트리거를 소거법으로 고정한다.

## 구성

- `case.js` — 시나리오 1개를 1회 실행하는 케이스 러너(별도 프로세스에서 spawn됨).
  글로벌 qmd의 node-llama-cpp(v3 ESM — 동적 import)와 모델 캐시를 그대로 쓴다.
- `matrix.js` — 시나리오별 N회 spawn·집계. 콘솔 표 + `results-<ts>.json`.
- `results-*.json` — 실행 기록(환경 스탬프·크래시 마커·ggml-cuda 라인·VRAM).

## 시나리오와 소거축

| ID | 내용 | 소거/검증 대상 | 결과(2026-11-21, 5회) |
|---|---|---|---|
| S1 | `qmd query` 풀스택(확장 1.7B→임베드→리랭크) | 기준선 — 크래시 재현 확인 | **4/5 크래시** ggml-cuda.cu:106 |
| S2 | 임베딩만(embeddinggemma, 컨텍스트 1개) | 임베더 단계가 씨앗인지 소거 | 0/5 |
| S3 | 리랭크만(Qwen3-Reranker, 컨텍스트 1개, 순차) | 리랭커 모델·rankAll 연산 축 | 0/5 |
| S4 | 임베드 상주 + 리랭크(폐기 없이) | 모델·컨텍스트 **공존** 축 | **3/5 크래시** |
| S5 | 리랭크 컨텍스트 2개 병렬(`llm.js:1350` 재현) | #519 **동시성** 축 — 양성 대조군 | 0/5 |
| S6 | 임베드 완전 폐기(컨텍스트+웨이트)→리랭크 | 상주가 필요조건인지 판정 | 0/5 |
| S7 | 임베드 **컨텍스트만 폐기**(웨이트 상주)→리랭크 | 컨텍스트 vs 웨이트 축 분리 | 0/5 |

## 판정 (2026-11-21 확정)

**트리거 = 살아있는 임베드 컨텍스트가 상주한 채 rankAll이 실행되는 것.**

- 필요조건 실증: 컨텍스트가 살아있으면 터진다(S4 3/5, S1 4/5), 폐기하면
  안 터진다(S6·S7 0/5). **웨이트 상주는 무관**(S7) — 컨텍스트 버퍼만이 문제.
- 기각: 리랭커 모델 단독 결함(S3), #519 동시 랭킹 컨텍스트(S5 — 랭킹 2개
  병렬은 멀쩡), 임베더 단독(S2), 전환 이력 오염(S6·S7).
- 임베드 컨텍스트는 크래시 순간 **유휴**다(동시 실행이 아니다) — 상주만으로
  터지는 ggml-cuda 버퍼·그래프 결함. 크래시 시 여유 VRAM ≈6.7GB(가짜 OOM 수치 증명).
- qmd는 임베드 풀을 5분간 웜유지하므로 `qmd query`는 매번 트리거 조건을
  만든다 — S1 4/5와 정합.
- 크래시는 확률적(60~80%) — 0/5는 무크래시 '경향'의 증거이지 부재 증명이 아니다.

## 처방 방향 (카드 4)

리랭크 전 임베드 컨텍스트 폐기(웨이트 유지) → 리랭크 후 재생성. S7이 그
구성으로 0/5. 컨텍스트 재생성은 웨이트 재로드가 아니므로 저렴하다. qmd 상류
패치가 원형 — 이 하네스의 S4가 상류 리포트용 최소 재현 케이스다.

## 주의

- 크래시 판정은 stderr `CUDA error` 마커 + 비정상 exit code — 둘 다 매 run에 기록된다.
- 이 하네스는 **llm-wiki 소스를 건드리지 않는다**(vulkan 강하 efe4c14 유지).
- 모델·버전 동일성이 재현 조건: qmd 2.8.3 / node-llama-cpp 3.20.0 / 드라이버 610.47
  (결과 JSON의 meta에 스탬프됨).
