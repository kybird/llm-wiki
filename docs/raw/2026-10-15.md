## Case 1: 무소속 마일스톤 + 사후 편입 — "제3의 상태" 철회 (사용자 판정)
- Problem: 인터럽트가 무소속(소속 필드 없음)으로 떠 있으니 보드에서 목적 없이
  흩어져 보인다. 사용자: "각각의 카드는 마일스톤에 종속되어야 한다."
- Insight: 무소속을 **예약 제목의 실제 마일스톤**(`conclusion: never` — 종료 규칙의
  데이터화)으로 만들면 개념은 하나 유지한 채 "소속 없는 카드 0장"이 기계적으로
  보장된다. 종결 카드 수집은 **사후 편입**(`--retro "<사유>"`) — 종결 마일스톤은
  불변(verdict의 "상태 불변, 이력 append"와 같은 길), 주제 수정은 항상 새
  마일스톤. 재오픈 안 함: milestone-done 이중 집계 churn + 타임라인 정직성.
- Evidence: 브레인스토밍 3축(가상 그룹핑/실카드/신규 kind) 제시 → 사용자 "2번,
  마일스톤은 각자의 종료 규칙을 가진다" → "무소속은 종결되지 않는다, 대신 종결된
  애들을 사후에 묶는다" → 불변 vs 재오픈 재질문에 불변 확정. 설계 문서
  docs/superpowers/specs/2026-10-14-unassigned-milestone-retro-design.md, plan.md
  3.8 개정.
- Action taken: 4카드 마일스톤으로 구현 완료(전원 종결, c873b52~2ee8e35).
  card new 기본 소속+무소속 자동 생성, --retro 감사 3종(카드 Notes·마일스톤
  Result·activity), 봉인 무소속 비적용, 해제=무소속 환원(필드 삭제 경로 제거),
  board/report/lint/monitor 분리 표기·방치 묶음 지적. 134/134 통과.

## Case 2: 모니터 내장 클라이언트 스크립트에 백틱을 넣으면 외부 템플릿이 깨진다
- Problem: kanban-monitor.js의 클라이언트 JS는 서버 파일 안 큰 템플릿 리터럴에
  내장돼 있다. 렌더 로직에 템플릿 리터럴(백틱)을 쓰는 수정을 넣는 순간 외부
  리터럴이 거기서 닫혀 `SyntaxError: Unexpected identifier '대기'` — CLI 전체가
  죽고 12개 테스트가 동시에 빨개졌다.
- Insight: 내장 스크립트 수정에는 **문자열 연결만** 쓴다. 그리고 이 파일이
  깨지면 bin이 로드 단계에서 죽으므로 "관련 없어 보이는 테스트 다수 실패" =
  로드 실패 신호로 읽는다.
- Evidence: lib/kanban-monitor.js:607 — `대기 ${...}` 백틱 한 줄이 원인, 연결로
  교체해 즉시 133/133 복구.
- Action taken: 문자열 연결로 수정. [[ui-changes-need-browser-verification]]의
  파싱 게이트 테스트가 있어서 로드 확인은 노드 테스트가 잡아줬다.

## Case 3: pick은 위치 인자를 무시한다 — --card 플래그가 유일한 지정 경로
- Problem: `llm-wiki pick "제목"`이라 치면 제목을 무시하고 ordinal 순서상 첫
  eligible 카드를 집어버린다(웹 뷰 카드를 의도치 않게 클레임).
- Insight: 지정 집기는 `pick --claim <name> --card <title>`만 지원한다. 잘못
  집었으면 `unpick <title> --why "…"`로 되돌린다(사유 필수).
- Evidence: bin/llm-wiki.js:58 사용법. 2026-10-15 세션 실측 — unpick+재지정으로
  수습.
