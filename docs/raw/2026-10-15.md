## [2026-10-15 design] Case 1: 무소속 마일스톤 + 사후 편입 — "제3의 상태" 철회 (사용자 판정)

### Grounding
- Git Context: `hash:c873b52`→`2ee8e35` (설계 승인 → 4카드 구현), `hash:fda39cb`(0.8.0)
- Evidence: 브레인스토밍 3축(가상 그룹핑/실카드/신규 kind) 제시 → 사용자 "2번, 마일스톤은 각자의 종료 규칙을 가진다" → "무소속은 종결되지 않는다, 대신 종결된 애들을 사후에 묶는다" → 재질문에 불변 확정. 설계 문서 docs/superpowers/specs/2026-10-14-unassigned-milestone-retro-design.md, plan.md 3.8 개정.
- Confidence: 5/5

### 검색 단서
카드 마일스톤 안 붙음, 소속 없는 카드, 인터럽트 착지, card new --milestone 기본, conclusion never, 사후 편입, retro, 종결 마일스톤 재오픈, reopen, 범위 변경 scope-amend, plan.md 3.8

### 상황
인터럽트(사용자 요청·버그·follow-up)가 무소속(소속 필드 없음)으로 떠 있어 보드에서 목적 없이 흩어져 보인다 — 사용자: "각각의 카드는 마일스톤에 종속되어야 한다."

### 가설
(가) 뷰에서만 무소속 그룹으로 묶어 표시 — 데이터는 소속 없음 유지. (나) 실제 마일스톤 카드 — 단 무소속은 종결 시 재생성(에포크). (다) 종결 카드 편입은 기존 종결 마일스톤 재오픈으로 흡수 — "소프트웨어는 계속 변경되니까". 기각: (가)는 데이터 불변식이 아니고 보이는 것만 해결, (나)는 인터럽트 1건마다 에포크 1개로 이력 오염, (다)는 verdict가 확립한 "종결은 상태 불변, 이력은 append"를 깨고 milestone-done 이중 집계 churn.

### 판정
무소속은 예약 제목의 실제 마일스톤(`conclusion: never` — 종료 규칙의 데이터화) — 개념 하나 유지한 채 "소속 없는 카드 0장"이 기계적으로 보장된다. 종결 카드 수집은 사후 편입(`--retro "<사유>"`)으로 항상 **새(또는 진행 중) 마일스톤** — 종결 마일스톤은 불변, 주제 수정은 새 마일스톤 에포크로 기록. 재오픈 안 함: 타임라인 정직성("X 계획은 그날 끝났다"가 영원히 참).

### 조치
4카드 마일스톤으로 구현 완료(전원 종결, 0.8.0 출하): card new 기본 소속+무소속 자동 생성, --retro 감사 3종(카드 Notes·마일스톤 Result·activity), 봉인 무소속 비적용, 해제=무소속 환원, board/report/lint/monitor 분리 표기·방치 묶음 지적. 134/134 통과.

## [2026-10-15 discovery] Case 4: pick은 위치 인자를 무시한다 — --card 플래그가 유일한 지정 경로

### Grounding
- Evidence: bin/llm-wiki.js:58 사용법 `pick --claim <name> [--card <title>]`. 이날 세션 실측 — `llm-wiki pick "무소속 자동 생성과 기본 부착"`이 '웹 뷰 — 드래그 이동'(ordinal 첫 eligible)을 클레임.
- Confidence: 5/5

### 검색 단서
pick 잘못 집음, 다른 카드 클레임, unpick, pick 제목 지정, --card 플래그, 위치 인자 무시

### 상황
`llm-wiki pick "제목"`처럼 제목을 위치 인자로 주면 무시되고 ordinal 순서상 첫 eligible 카드를 집어버린다 — 의도치 않은 카드가 doing+클레임된다.

### 가설
제목 매칭이 안 되는 버그인가 — 아니, 설계상 지정 집기는 --card 플래그만 지원하고 위치 인자는 조용히 버린다.

### 판정
지정 집기는 `pick --claim <name> --card <title>`만. 잘못 집으면 `unpick <title> --why "…"`(사유 필수)로 되돌린다.

### 조치
unpick+재지정으로 수습(--why에 사유 기록). work-loop 스킬 사용례에 --card 명시.

## [2026-10-15 discovery] Case 5: 저장은 성공, 회수는 실패 — 완결된 설계를 내 메모리에서 못 찾고 재유도했다

### Grounding
- Evidence: harness memory "episode-memory-refinement-intent"(같은 날 이른 컨텍스트가 저장 — 골격·카파시 분석·README 오기까지 완결)이 세션 색인에 있었는데, 사용자의 "카파시 원안에 제안 없나?" 질문에 웹검색으로 전부 재유도. 사용자 지적: "이건 카파시의 문제가 아니라 너가 wiki-search에 어떤 단어를 넣는 경향이 있느냐가 문제지".
- Confidence: 5/5

### 검색 단서
이미 아는 걸 다시 조사, 메모리 회상 실패, 검색 단서, 어휘 갭, 안 상태 모르 상태, 질의 로깅

### 상황
직전 컨텍스트가 남긴 완결된 설계 기록이 색인에 존재했는데, 질문을 받는 순간 "내가 이미 아는가?"라는 쿼리 자체가 떠오르지 않았다.

### 가설
기억이 안 나는 게 아니라 **회상 트리거가 없다** — 세션 시작 의식(주제어 1회)·에러 문자열 검색만이 절차화돼 있고, "질문 → 내 기억 먼저" 경로가 절차에 없다.

### 판정
기록은 "안 상태의 나"(교휸에 이름 붙인 어휘)가 하고 검색은 "모르는 상태의 나"(증상의 어휘)가 친다 — 간극이 구조라서 규율로 못 막고 어휘 계약(검색 단서)과 측정(질의 로깅)로 막는다.

### 조치
2026-10-15 설계로 이식 — 검색 단서 고정 섹션, search-queries.jsonl 질의 로깅, compile 환류, work-loop pick 훅. 이 Case 자체가 첫 검색 단서 견본.
