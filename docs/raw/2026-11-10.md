### Error
TTSTextViewer에서 로컬 진화한 스킬(work-loop v14, kanban-plan v7 — 2026-10-15 무소속 규약·8a 포함)이 노트북의 0.6.0 글로벌 CLI 자동 갱신에 구템플릿으로 되돌려졌다. 되돌림 자체도 문제지만 **감지가 실패한 게 핵심 결함**: 양쪽 모두 버전 번호가 같아(이중 카운터) 도구가 "버전 같음=정상"으로 판정했다.

### Analysis
- **마커 판정의 허점**: syncMarkedFiles는 "복사본에 마커가 살아있으면 미수정 → 정본이 이긴다"였다. 로컬 진화는 마커 줄을 유지(심지어 독립 bump)하므로 진화본이 항상 '미수정'으로 오판된다. 마커 삭제만이 유일한 보호였는데, 그건 "영구 포크" 선언이라 진화→정본 회귀 경로가 없다.
- **wiki계 스킬은 다른 이유로 갱신 안 됨**: 마커 이전(script-era, ≤0.6.0)에 시드돼 마커가 아예 없어 'user-modified'로 영구 스킵 — `node .claude/skills/*/scripts/*.js` 시대 유물이 살아있는 원인.
- **감지 축 처방**: 내용 비교는 버전 순서와 함께 읽혀야 한다 — 로컬 버전 < 정본 버전 = 정상 갱신, 로컬 ≥ 정본 + 내용 상이 = 분기(diverged) = 절대 불복사(--yes 포함). 내용 비교·해시는 EOL 정규화 뒤에(git clone autocrlf가 CRLF 체크아웃해 환각 분기·환각 diff를 만든다 — 실측: clone 정본 해시 ≠ 작업 트리 정본 해시).
- **잔여 구멍(인지하고 남겨둠)**: 로컬 진화가 버전 bump 없이 낮은 번호에 머무르면 정상 갱신으로 위장돼 덮인다. 레포 커밋 추적(기준 해시 원장)이 근본 처방이나 상태 파일 계약이 커져 이번 범위에서는 README 업그레이드 순서(역류 먼저 → npm i -g → sync)로 절차적 봉쇄.

### Fix Code

```
syncMarkedFiles(init·auto-update 공유): destVer >= srcVer && 내용 상이 → status 'diverged'(해시·버전 보고, 불복사)

```
