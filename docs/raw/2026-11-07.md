## Case 2: qmd CLI — collection list는 경로 미노출, collection show가 Path 노출

### Grounding
- Git Context: `hash:85d80e7`
- Evidence: `qmd collection list`·`qmd collection show ttswiki` 실측 출력(@tobilu/qmd 2.8.3, 글로벌)
- Confidence: 5/5

### Discovery
`qmd collection list` 출력은 이름(qmd:// URI)·Pattern·Files·Updated만 노출하고 경로가 없다 — list 출력 파싱으로는 등록 경로 검증 불가(이것이 syncQmd가 경로를 못 보는 구조적 이유). 대신 `qmd collection show <name>`이 전용 뷰로 `Path:` 행을 노출한다:
```
Collection: ttswiki
  Path:     D:\Project\TTSTextReader\TTSTextViewer\doc\wiki
  Pattern:  **/*.md
  Include:  yes (default)
```
하위명령 구성: `qmd collection add/list/remove/rename/show`. `collection list`는 컬렉션별 `Files: N`(색인 파일 수)도 준다 — update 직후 list 재조회로 "대상 디렉터리에 .md 있는데 0건 색인" 경고를 update 출력 캡처 없이 검출 가능(stdio inherit 라이브 진행 보존).

### Analysis
- Why non-obvious: list에 없는 정보가 show에만 있다 — syncQmd 수정 시 자연스럽게 list 파싱을 확장하려 들면 벽
- Impact: 경로 드리프트 자가치유(B)와 0건 색인 경고(C)의 구현 통로 확정. index.yml 직접 수정 없이 qmd CLI 경유 유지("다른 도구 설정 파일 직접 수정 금지" 원칙 준수)
- Action taken: 카드 AC에 구현 통로로 봉인

### Grounding

- Confidence: 5/5

### Error
정본 레포에서 전역 `llm-wiki card new "…" --goal … --ac …` 실행 → 카드 생성 성공 출력에 `milestone: 무소속`이 빠지고, 생성된 카드 frontmatter에 milestone 필드 자체가 없음. 보드 무소속 집계 불변(0/4)으로 발견. 오류 메시지 없음 — **조용한 계약 위반**.

### Environment Context
- Packages: 전역 @kybird/llm-wiki 0.6.0(무소속 기본 소속 규약 2ee8e35=0.8.0 이전) / 레포 HEAD 0.8.0
- Migration Issue: Yes — 0.8.0 npm 발행 누락(사용자 터미널 필요)으로 전역이 낡은 채 방치

### Fix Code
```bash
node bin/llm-wiki.js card edit "QMD 컬렉션 경로 드리프트 자가치유" --milestone "무소속"
```

### Analysis
- Root cause: 정본 레포의 보드를 전역 CLI로 쓰면, 전역 버전에 없는 신규 규약(무소속 기본 소속)이 에러 없이 스킵됨 — 0.8.0 코드(ensureUnassigned)는 정상
- Why it failed: 버전 스큐가 "명령 성공+규약 누락"으로 나타남 — CLI의 성공 출력이 규약 준수를 보증하지 않음
- How it was fixed: 정본 bin으로 소속 부착 + 운용 규칙 "정본에서 카드·보드 쓰기는 `node bin/llm-wiki.js`" (메모리 갱신). 근본 해결은 0.8.0 npm 발행 후 전역 갱신
- 감지 그물: 보드 마일스톤 집계 수와 카드 수 불일치 — "무소속 무소속 카드 0장"이 규약인데 기계 보증이 전역 스큐 앞에서 무력
