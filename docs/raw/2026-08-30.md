## Case 1: npm 스코프 패키지는 --access public 없으면 조용히 비공개로 발행된다

### Grounding
- Git Context: `hash:d3ba05e`
- Evidence: npm registry (@kybird/llm-wiki), npm publish 로그
- Confidence: 5/5

### Error
npm error 403 403 Forbidden - PUT https://registry.npmjs.org/@kybird%2fllm-wiki - Two-factor authentication or granular access token with bypass 2fa enabled is required to publish packages.

2FA를 통과한 뒤 --access public을 빠뜨리고 재발행하면 성공 출력("+ @kybird/llm-wiki@0.2.0")이 나오지만 패키지는 비공개다. 이후 npm view는 404를 뱉고:

npm error 403 403 Forbidden - PUT https://registry.npmjs.org/@kybird%2fllm-wiki - You cannot publish over the previously published versions: 0.2.0.

### Environment Context
- Packages: npm 11 (node 24), 2025-11 보안 정책 적용 레지스트리
- Migration Issue: Yes

### Fix Code
`npm publish --access public` — 스코프 패키지의 기본값은 private이라 플래그 필수.
2FA 정책은 publish 시점에 브라우저 웹 인증 플로우로 풀린다("Authenticate your account at …").

### Analysis
- Root cause: 스코프 패키지의 기본 접근 수준이 restricted인 것 + 2025-11부터의 2FA 강제.
- Why it failed: 성공 출력("+ pkg@version")이 나도 비공개면 외부 조회는 404다.
  진짜 존재 증명은 재발행 시의 "You cannot publish over" 버전 충돌 에러 — 레지스트리
  문서 404여도 버전 충돌이 나면 존재하는 것이다(진단 순서: 404 → 재발행 시도 → 충돌).
- How it was fixed: --access public으로 재발행. CI 전환 시 granular token(bypass 2FA)이 같은 역할.

## Case 2: 질문 타이밍은 "누가 대답할 수 있는가"가 결정한다

### Grounding
- Git Context: `hash:7c03105`
- Evidence: skills/kanban-plan, skills/work-loop
- Confidence: 4/5

### Design Decision
시작 전 질문(사람 있는 세션)과 벽에서 park(무인 세션)을 분기하는 규칙을 스킬에 명문화.
handoff 질문은 "끝나고 물어보기"가 아니라 "판정을 사람에게 넘기기"다.

### Alternatives Considered
- Option A: 무인 루프도 시작 전 승인 대기 — 2.1 확정(승인 대기 = 오프피크 낭비)과 정면충돌. 기각.
- Option B: 질문 메커니즘을 둘로 분리 구현 — 같은 handoff/resume으로 충분(비동기 질문도
  card+handoff → 답 → resume). 새 명령 불필요. 기각.
- Selected: kanban-plan에 "시작 전 질문이 제일 싸다" 명시 + work-loop 규칙 2에
  "handoff 질문은 벽 도달 기록" 명시.

### Analysis
- Context: 보통 에이전트는 시작 전에 묻는다 — 무인 루프의 "끝나고 물어보는" 흐름과
  혼동되지 않게 세션 모드별 규칙이 필요했다.
- **Trade-offs**: 무인 처리량 vs 질문 지연 — 밤새 모아 아침에 일괄 응답이 설계다.
- Reversibility: High

## Case 3: lastCompiled를 UTC로 계산하면 KST 자정~9시에 당일 로그가 전부 'new'로 재보고된다

### Grounding
- Git Context: `hash:4c5f27c`
- Evidence: doc/wiki/compile-state.json, pre-commit 훅 출력
- Confidence: 5/5

### Error
compile index 직후인데도 pre-commit 넛지의 compile list가 당일 로그를 "New/Modified"로 보고했다.

### Discovery
compile index는 lastCompiled를 UTC 오늘로 계산했고(당시 UTC 08-29), raw 헤더 날짜는
현지(KST 08-30)였다. 날짜 기준이 두 곳에서 달라 자정~9시 동안 비교가 어긋난다.

### Analysis
- Why non-obvious: 낮에는 증상이 없다. 자정~9시에만 발생 — 사용량이 적은 머신에서는 영영 못 본다.
- Action taken: localToday 헬퍼로 날짜 기준을 현지로 통일. 단조 가드(max 이전, 오늘)는 유지.
- 날짜를 쓰는 모든 비교는 값뿐 아니라 기준 시간대까지 통일해야 한다.
