## Case 2: pick 위치인자 함정 재발(2회차) — 조용한 무시에서 이름을 말하는 실패로

### Grounding
- Git Context: 10-15 raw 문서화(`hash:85d80e7` 커밋 제목에도) → 11-08 오클레임 사고로 재발
- Evidence: docs/kanban/activity.jsonl(claimed 웹 뷰 → unpicked → claimed QMD) · lib/kanban-cmd.js pick
- Confidence: 5/5

### Error
`llm-wiki pick "QMD 컬렉션 경로 드리프트 자가치유"` — 의도와 다르게 ordinal 최저 카드(웹 뷰 — 드래그 이동, 6000)가 집혔다. 위치인자가 조용히 무시됐다(에러 메시지 없음 — 침묵이 결함). 문서화된 함정(10-15)을 검색 없이 재차 밟았다.

### Fix Code
```js
if (positional.length) {
  fail(`pick은 위치인자를 받지 않는다: ${positional.join(' ')} — 지정 집기는 pick --card "<제목>" (USAGE 참고)`);
}
```
실측: `✗ pick은 위치인자를 받지 않는다: x — 지정 집기는 pick --card "<제목>" (USAGE 참고)` (exit 1)

### Analysis
- Root cause: pick은 7개 루프 명령 중 유일하게 위치인자를 받지 않는데(나머지는 `<제목>` 규격) validateFlags는 플래그만 검증하고 위치인자는 버렸다 — "모르는 토큰은 실패" 계약의 위치인자 사각지대
- How it was fixed: 오클레임은 `unpick "<제목>" --why "…"`로 반납(사유 기록), 가드로 재발 차단(회귀테스트: 위치인자 exit 1 + 어느 카드도 안 집힘 + --card 불변)
- 함정은 문서화만으로 안 막힌다 — 2회차 발화가 증거. 기계적 가드(실패)가 유일한 예방
- 부수: unpick의 `--why` 필수 계약이 오클레임 반납을 사유 기록과 강제로 묶어 아침 리뷰가 집기-취소 패턴을 보게 한다 — 설계 의도대로 작동

## Case 3: 함정 클래스 스윕 — init이 두 번째 조용-오실행 결함, 나머지는 무해 삼킴

### Grounding
- Git Context: pick 가드(1d52fba) 직후 스윕 — bin/llm-wiki.js dispatch 전수 리드
- Evidence: bin/llm-wiki.js:161 `init({ check: args.includes('--check') })` · skills.dispatch(unknown subcommand → exit 1) · 제목 8명령(findCard 실패 → loud)
- Confidence: 5/5

### Discovery
pick 수정 뒤 같은 클래스(위치인자 조용한 무시)를 전 명령으로 스윕한 결과:
- **조용-오실행이 부작용을 내는 경로는 pick과 `init` 둘뿐** — `init check`(--check를 단어로 친 오타)가 판정 전용이 아니라 풀 init(스캐폴딩 쓰기)을 조용히 실행했다. 가드로 수습(위치인자 → 이름 말하고 실패, exit 1, 아무것도 안 씀). 회귀테스트: 오패 실패+무쓰기, bare init·--check 불변.
- 제목 받는 8명령(done·handoff·unpick·supersede·abandon·reopen·resume·verdict)은 제목이 안 풀리면 큰소리로 실패 — 조용 리다이렉트 경로 없음.
- 읽기 전용(lint·board·monitor·wait·compile 잉여 토큰·skills 잉여 인자)은 삼키지만 무해 — 다만 "어디는 엄격, 어디는 관대"는 [[agent-cli-contract]] 균일 원칙 위반. 스킬 프롬프트는 함정 문법을 가르친 적 없음(work-loop는 `pick` 단독·`unpick <제목>`만) — 함정 문법은 에이전트가 형제 명령 패턴으로 재발명하며, 이제 가드 에러 메시지가 그 자리에서 교정한다.

### Analysis
- Why non-obvious: 스윍 전엔 pick이 유일한 결함인지 알 수 없었다 — 클래스 관점에서 봐야 init의 오타→쓰기 변환이 보인다
- Action taken: init 가드 즉시 수정(부작용 결함), 읽기 전용 통일(모든 명령의 위치인자 arity·알 수 없는 플래그 균일 검증)은 카드 "CLI 위치인자·플래그 균일 계약"으로 백록 — 무해 계약 통일은 기능 경계(카드+게이트)
- 함정 문법 출처가 프롬프트가 아니라는 것도 스윕 소득 — 전파 채널(skills/)은 침묵하고, 사용자(에이전트)의 패턴 추측이 범인
