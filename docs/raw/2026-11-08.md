## Case 2: pick 위치인자 함정 재발(2회차) — 조용한 무시에서 이름을 말하는 실패로

### Grounding
- Git Context: 10-15 raw 문서화(`hash:85d80e7` 커밋 제목에도) → 11-08 오클레임 사고로 재발
- Evidence: docs/kanban/activity.jsonl(claimed 웹 뷰 → unpicked → claimed QMD) · lib/kanban-cmd.js pick
- Confidence: 5/5

### Error
`llm-wiki pick "QMD 컬렉션 경로 드리프트 자가치유"` — 의도와 다르게 ordinal 최저 카드(웹 뷰 — 드래그 이동, 6000)가 집혔다. 위치인자가 조용히 무시됐다(에러 메시지 없음 — 침묵이 결함). 문서화된 함정(10-15)을 검색 없이 재차 밟았다.

### Fix Code
```js
if (positional.length) {
  fail(`pick은 위치인자를 받지 않는다: ${positional.join(' ')} — 지정 집기는 pick --card "<제목>" (USAGE 참고)`);
}
```
실측: `✗ pick은 위치인자를 받지 않는다: x — 지정 집기는 pick --card "<제목>" (USAGE 참고)` (exit 1)

### Analysis
- Root cause: pick은 7개 루프 명령 중 유일하게 위치인자를 받지 않는데(나머지는 `<제목>` 규격) validateFlags는 플래그만 검증하고 위치인자는 버렸다 — "모르는 토큰은 실패" 계약의 위치인자 사각지대
- How it was fixed: 오클레임은 `unpick "<제목>" --why "…"`로 반납(사유 기록), 가드로 재발 차단(회귀테스트: 위치인자 exit 1 + 어느 카드도 안 집힘 + --card 불변)
- 함정은 문서화만으로 안 막힌다 — 2회차 발화가 증거. 기계적 가드(실패)가 유일한 예방
- 부수: unpick의 `--why` 필수 계약이 오클레임 반납을 사유 기록과 강제로 묶어 아침 리뷰가 집기-취소 패턴을 보게 한다 — 설계 의도대로 작동
