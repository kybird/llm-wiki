## Case 1: 시맨틱 검색층 12일 전면 사망 — import 누락 ReferenceError가 catch에 삼켜져 "No semantic results."로 위장

### Grounding
- Git Context: `hash:2722b01` (결함 도입은 `214e8c2`, 2026-09-09)
- Evidence: lib/wiki-search.js(수습 전 — import 없는 execFileSync 호출), 복제 실험(같은 execFileSync 호출을 child_process require와 함께 직접 실행 시 llm-wiki-wiki 83%·llm-wiki-wiki-raw 81% 정상 반환 — 같은 인자로 llm-wiki 경유 시에만 빈 결과), npm test 88/88, 부정 게이트 실증(import 제거 시 test/wiki-search-qmd.test.js 2/2 실패)
- Confidence: 5/5

### Error
`No semantic results.` — 모든 질의·모든 세션·12일간(2026-09-09 ~ 2026-09-22). 내용물은 `ReferenceError: execFileSync is not defined` (214e8c2가 qmd 호출을 execFileSync로 바꾸며 `const { execFileSync } = require('child_process')`를 빠뜨렸다).

### Environment Context
- Packages: @kybird/llm-wiki 0.4.2(전역 설치 실측) / 0.5.0(레포 HEAD — 동일 결함) / @tobilu/qmd 2.8.3
- Migration Issue: No

### Fix Code
lib/wiki-search.js — 상단 import 추가. 아울러 catch가 에러를 버리지 않고 결과 봉투의 `semantic.errors`에 실어, 사람용 출력에 `(QMD error on <collection>: <message>)` 줄로 드러낸다.

### Analysis
- Root cause: 두 겹. ① import 누락(동작 불능) ② catch의 무조건 삼킴(불능이 "정상 한계"와 구분 불가한 출력으로 위장). 같은 날 compile쪽(카드 '컴파일·검색 잔여 정리' AC#3 — wiki-compile.js:22)은 import를 챙겼다 — 같은 리팩터의 한쪽만 살아남은 것.
- Why non-obvious: 인덱싱 경로(compile index → qmd collection add/update/embed)는 계속 살아 컬렉션이 최신으로 갱신됐다(qmd status: 16문서, 갱신 14시간 전). 그래서 "wiki-compile로 지식은 잘 남는데 어느 세션도 못 찾는다"는 증상이 되고, 위장 문자열이 정상 한계(2026-09-02의 "No semantic results" 3단 진단 1~3분기)와 소리가 같아 진단이 늦었다.
- Impact: 시맨틱 재현율 0 — grep(literal substring)만 살아남아 어휘 불일치 질의(교차언어·설명투)는 전멸. 2026-09-02 실측 "시맨틱 91~94% 히트"는 결함 이전 측정이라 부활 후 재측정이 필요하다.
- How it was fixed: import 1줄 + 에러 전파. 회귀 테스트는 stub qmd(QMD_CLI_PATH)로 두 경로(정상·고장)를 게이트한다 — import를 지우면 정상 경로 테스트가 즉시 실패한다(실증).
- **Anti-Pattern**: catch에서 에러를 버리고 계속 진행 — 실패와 정상 한계가 같은 출력을 내는 순간, 죽은 층은 스스로를 "결과 없음"으로 위장한다.

## Case 2: qmd 2.8.3의 search는 BM25 전문검색 — 질의 확장·재순위는 query 명령에 있다

### Grounding
- Git Context: `hash:2722b01`
- Evidence: qmd 2.8.3 `--help` — "qmd query <query> - Hybrid search with auto expansion + reranking (recommended)", "qmd search <query> - Full-text BM25 keywords (no LLM)". 실측: 질의 "패키지를 공개했는데 찾을 수 없음" → `qmd search -c llm-wiki-wiki` "No results found."([[npm-scoped-publishing]] 페이지가 wiki에 있음에도)
- Confidence: 5/5

### Discovery
llm-wiki가 호출하는 `qmd search`는 벡터·LLM 없는 BM25 키워드 검색이다. 어휘 불일치(교차언어·설명투 질의)를 흡수하는 질의 자동 확장 + 재순위는 `qmd query`에 있다 — llm-wiki는 그것을 아직 쓰지 않는다.

### Analysis
- Why non-obvious: llm-wiki 출력 라벨이 "Semantic search via QMD"라 실측 없이 시맨틱하다고 믿게 한다.
- Impact: 검색층 부활 후에도 어휘 불일치 재현율은 BM25 한계에 묶여 있다.
- Action taken: 별도 카드(query 전환 + 구버전 qmd 폴백)로 백로그 등록.
