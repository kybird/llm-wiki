## Case 2: 모니터 UI 검증 함정 3종 — 템플릿 NUL·IAB -webkit-box 무시·require 캐시

### Grounding
- Git Context: `hash:b21b498`
- Evidence: 서빙 페이지 바이트 스캔 NUL@11663 → 주석 수정 후 renderMonitorPage() 산물 NUL 부재 실측; getComputedStyle로 IAB 웹뷰 display 계산값 `flow-root` 확인(-webkit-box 무시); q 클램프 max-height 폴백 적용 후 clientHeight 209→49
- Confidence: 5/5

### Discovery
세 함정 모두 "기능은 정상이라 결함이 숨는" 계열이다. (1) monitor 페이지는 백틱 템플릿 리터럴 안에 살아 있어서, 주석에든 문자열에든 **리터럴 `\u0000` 텍스트를 쓰면 렌더링 순간 진짜 NUL 바이트가 페이지에 실린다** — 소스 파일엔 NUL이 없어 Edit 도구·node --check·구문 게이트(new Function)가 전부 통과했다. (2) IAB 웹뷰 엔진은 `display:-webkit-box`를 계산값에서 flow-root로 흘려보내 `-webkit-line-clamp`가 조용히 무효 — max-height 폴백 필수. (3) monitor 서버는 require 시점 템플릿을 캐시 — 골격/CSS를 고친 뒤 브라우저 reload로는 반영 안 되고 서버 재시작이 필요하다(1차 실측 "클램프 안 됨"은 코드가 아니라 캐시 탓).

### Analysis
- Why non-obvious: 템플릿 안 이스케이프는 "주석이라 무해"가 성립하지 않는다 — 평가 결과물이 HTML 응답 바이트다. 페이지 검증은 눈이 아니라 `renderMonitorPage().includes('\x00')`처럼 산물 바이트를 직접 검사할 것.
- IAB에서 Playwright locator click이 액션어빌리티 대기에서 타임아웃 나는 경우 `evaluate("el.click()")` 프로그램 클릭으로 논리 검증 가능(2026-11-23 .ms-head 실측).
- Action taken: 주석을 실제 구현(공백 구분자)과 일치시켜 수습, 함정은 에이전트 메모리(llm-wiki-monitor-ui-verification-quirks)에도 저장.

### 가설
- PATH의 `qmd` 명령이 안 쓰이고 있다 → 확인: llm-wiki는 `findQmd()` 파일 경로로 실행하며 PATH 명령을 쓰는 곳은 없음(맞음)
- findQmd 후보 순서가 자기 트리를 글로벌보다 앞에 둠 → lib/find-qmd.js 읽기: ②자기 트리 → ③cwd → ④글로벌. 레포 안에서 실행하면 ②의 2.8.3이 반환되고 글로벌 2.9.0은 도달 불가(맞음)
- "레포 내부 사본만 지우면 해결" → 기각: npm install마다 optionalDependencies로 부활. 소비자 머신에서도 자기 트리 사본이 같은 방식으로 그림자가 될 수 있어 코드 수리가 필요

### 판정
루트코즈는 상류 크래시(2.9.0에서 수리됨)가 아니라 **해석 계층의 그림자**: auto-update B안이 관리하는 사본(글로벌)과 findQmd가 실행하는 사본(자기 트리, lockfile 동결)이 달라 채택 처방이 해석 단계에서 무력화됐다. syncQmd는 미설치 시 설치도 안 하고(`if (!o.qmdPkg) return null`) 버전 판정 기준조차 findQmd 결과물 — 업데이터와 해석기가 다른 사본을 보는 구조적 모순. 같은 실패 모드가 다른 머신 소비 레포(스킬 스크립트 경로 고정)에서 독립 관측: 결함은 특정 스크립트가 아니라 **고정 발견 순서 + 독립적으로 드리프트하는 사본들** 조합 자체다.
