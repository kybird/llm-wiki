## Case 2: 전파 갭 사고 — 배포·수리 에이전트가 자기 계약(doc→docs)을 몰랐다

### Grounding
- Git Context: 0.6.0(2026-10-03)이 레이아웃 계약을 docs/로 전환 — 코드·시드·README·위키 4곳에 지식 존재
- Evidence: TTSTextViewer 진단 세션 — `doc/`(위키 md 0개)와 `docs/wiki`(실제 위키) 공존, QMD 등록은 구경로 `doc\wiki`를 가리킴 · lib/init.js:224 "AGENTS.md already exists, untouched." · lib/find-doc-root.js:7 "레이아웃은 docs/가 정본"
- Confidence: 5/5

### Error
진단 에이전트(= 본 도구의 배포·수리 담당 세션)가 "QMD 등록 경로(doc\wiki)가 기대 경로와 일치하므로 자가치유가 발동하지 않는다 — 디렉토리가 그냥 비어 있다"라고 오판. 기대 경로 계산에 구계약(단수 doc)을 썼다. 실제로는 docRoot가 docs 우선으로 판정돼 불일치→재등록 발동이 정답. 에러 메시지가 없는 조용한 오판 — CLI가 아니라 **에이전트의 지식**이 낡았다.

### Analysis
- 3단 원인 사슬(실측): ① 운영 에이전트의 상시 지식면 2개 중 1개(세션 메모리 인덱스)가 전환 전 구판으로 오염(본문은 바른 채 — 매 세션 로드되는 건 인덱스뿐) ② 세션 시작 의식(`llm-wiki search`+`board`, AGENTS.md "매 세션 무조건")을 스킵 — wiki의 [[layout-migration]]이 검색으로 잡혔을 것 ③ **구조적 갭: 배포 산출물 중 AGENTS.md만 시드 이후 영구 동결** — skills·scripts·githooks는 마커 갱신되는데 "매 세션이 무조건 읽는 파일"만 updatedAt 시드 시점. 계약 변화가 소비 레포 에이전트에게 영영 전파되지 않는다.
- 사용자 판정: "메모리 문제가 아니라 업데이트 담당 에이전트에게 지시가 안 간 것" — 정확. 지식은 존재했으나 도달하지 않았다. 또한 수동 문서 패치(에이전트가 AGENTS.md 고치기)도 기각 — "llm-wiki를 업데이트하는 순간 저절로 수정되게" 설계해야 한다.
- 핵심 통찰: **npm update → 다음 명령 → syncCopies가 유일한 자동 접점(주입 차량)**이다. 이 차량에 안 탄 산출물은 전파가 안 된다.

### Fix Code
AGENTS.md 관리 섹션(lib/init.js syncAgentsSection + templates/AGENTS.md `llm-wiki:section` 마커):

- 세션 의식·보드 SSOT·스킬 트리거표와 함께 **레이아웃 계약(docs/ 정본, doc/ 레거시 폴백)을 섹션에 명문화** — 둘 다 있는 레포의 판정 근거 제공

### Analysis (설계)
- 왜 파일 전체 마커(스킬 방식)가 아닌 섹션 마커인가: AGENTS.md는 사용자가 아래에 자기 지시를 추가하는 파일 — 전체 덮어쓰면 마커를 지키며 추가한 사용자 영역까지 삼킨다. 섹션만 갈아끼우면 "이 파일은 네 것" 약속이 마커 밖에서 참으로 유지된다.
- 왜 append가 6.1 위반이 아닌가: "덮어쓰지 않는다"의 문언·정신 모두 추가가 아니라 파괴를 금지한다. append는 기존 바이트를 전부 보존한다.
- 도달 못 하는 면(한계, 명시): 손으로 쓴 AGENTS.md·CLAUDE.md/GEMINI.md 류는 마커가 없어 append 채택은 되지만(손본도 append됨) 내용 통합은 사람 몫. 채택 자체는 자동이다.
