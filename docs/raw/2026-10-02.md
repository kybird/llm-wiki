## Case 1: doc→docs 전환 — 첫 명령 자동 마이그레이션 설계(트리거 게이트와 판정 신호)

### Grounding
- Git Context: `hash:38b8f5d`
- Confidence: 5/5

### Design Decision
`doc/` → `docs/` 레이아웃 전환을 0.6.0에 실리며, 기존 레포는 **첫 llm-wiki 명령에서 자동 마이그레이션**(git mv doc docs)된다. 설계 3축:

1. **트리거 게이트** — bin 진입점에서 auto-update와 같은 명령 목록(search·compile·lint·skills·board·card·pick…resume)로만 발화. **wait·monitor·init은 제외**: wait·monitor는 stdout 첫 줄이 계약(이벤트 한 줄·URL)이라 마이그레이션 요약 몇 줄이 그 계약을 깨고, init은 자체 동기화 흐름이 있다. monitor는 추가로 docRoot를 열어두어 Windows에서 rename EPERM을 유발한다.
2. **판정 신호** — `doc/wiki` 존재 + `docs/` 부재만 마이그레이션 대상. wiki 하위 존재가 유일 신호라 init 흔적 없는 일반 doc/ 폴더는 건드리지 않는다. 마커 파일 불요 — 이동 성공 자체가 완료 상태(docs/wiki가 생김)라 다음 명령의 판정이 바뀐다.
3. **책임 분리** — findDocRoot는 사이드이펙트 없는 순수 리졸버로 유지(매 명령 여러 번 호출됨), 마이그레이션 발화는 bin 진입점 단 한 곳.

### Alternatives Considered
- Option A: 명시 명령 `llm-wiki migrate` — 타이밍 통제는 확실하나 소비 레포 10곳을 직접 돌아다녀야 하고 이중 레이아웃이 오래 공존. 기각.
- Option B: init 재실행에서만 — 가장 보수적이나 소비 레포가 init을 재실행할 보장이 없어 전환이 안 끝난다. 기각.
- Selected: 첫 명령 자동(옵트아웃 `migrateDocDir: false`) — autoUpdate(사본 자동 동기화)와 같은 집안 철학. 사용자가 두 결정(자동 트리거·0.6.0 편성)을 AskUserQuestion으로 확정.

### Analysis
- Context: 사용자 레포 반영 UX는 "npm update만 하면 된다"가 원칙 — 수동 단계는 그 서사를 깬다.
- **Trade-offs**: 자동성 vs 예측성 — git mv는 스테이징까지 해주므로 `git status`에서 즉시 보이고 revert 가능. 요약 출력은 auto-update 배너 선례로 허용.
- Reversibility: High — git rename이므로 전체 되돌림 한 커밋.
- 실패 경로: EBUSY/EPERM은 "연기 + 다음 명령 재시도"(명령 미차단), `docs/` 선점 시는 덮지 않고 보류 안내(매번 한 줄 — 조용히 포기하면 영영 전환 안 됨).

## Case 2: npm test의 명시 파일 목록이 새 테스트 파일을 조용히 삼킨다

### Grounding
- Git Context: `hash:38b8f5d`
- Evidence: package.json scripts.test(13개 파일 명시) vs test/ 디렉터리 15개 파일 — 신규 2종 미편입 상태에서 "npm test 88종 pass"
- Confidence: 5/5

### Error
에러는 나지 않았다 — **과장된 성공**이었다. C1 done 카드에 "test/find-doc-root-layout.test.js 6종 신설 — npm test 88종 전부 통과"라고 기록했지만, 그 파일은 npm test의 명시 목록 밖이라 스위트가 한 번도 실행한 적이 없었다. npm test는 여전히 88종(구 파일만)을 돌려 통과 — 신규 테스트의 부재를 전혀 반영하지 못했다.

### Environment Context
- Packages: node --test (npm test 스크립트가 `node --test test/a.test.js test/b.test.js ...` 형식으로 파일 목록을 명시)
- Migration Issue: No

### Fix Code
```json
"test": "node --test test/roundtrip.test.js ... test/find-doc-root-layout.test.js test/migrate-doc-dir.test.js ..."
```
+ C1 done 카드에 정정 노트 기록(카드 편집은 CLI, 기록은 남김).

### Analysis
- Root cause: `node --test <파일 목록>`은 명시된 파일만 돌린다 — 디렉터리 지정(`node --test test/`)과 달리 새 파일은 목록 편입 전까지 **조용히 무시**된다. 통과 개수(88)는 늘지 않으니 "테스트가 늘었다"는 감각으로는 탐지 불가.
- Why it failed: "npm test 통과"를 새 테스트의 실행 증거로 착각. 통과의 의미는 목록이 정의한다 — 목록 밖 테스트의 통과는 void다. done Result에 쓴 문장("6종 신설 — 88종 통과")은 독자가 둘을 연결하게 쓰여 있어 과장이 됐다.
- How it was fixed: C2에서 목록 편입(두 파일 모두) + C1 done 카드에 정정 노트(사용자 감사 규약 — 결함 처분을 기록으로만 끝내지 않기). 이후 전체 스위트 100종에서 폴백 테스트 ENOENT가 드러난 것(Case 3)이 편입의 실익 증명.

### Related Knowledge
- Concepts: [[card-file-anatomy]]
- Patterns: [[write-validation-matches-read-semantics]] — Result 문장의 증거 범위를 실제 실행과 일치시켜야
- **Anti-Patterns**: 증거 없는 done(QA 루프가 되돌림) — 이 사례는 "증거가 있으나 목록 밖"이라 스스로 정정해야 하는 변형

## Case 3: realpathSync 기반 경로 비교 헬퍼는 존재하지 않는 경로에서 깨진다

### Grounding
- Git Context: `hash:38b8f5d`
- Confidence: 5/5

### Error
```
Error: ENOENT: no such file or directory, realpath 'C:\Users\admin\AppData\Local\Temp\kb-layout-empty-xyFD8n\sub-yUFjMp\docs'
    at realpathSync.native (node:fs:2837:18)
```
독립 실행이 아니라 전체 스위트에서만 실패(파일 목록 편입 후 처음 실행됨).

### Environment Context
- Packages: node:test, Windows
- Migration Issue: No

### Fix Code
```js
// realpath 없는 문자열 비교(폴백 경로는 존재하지 않을 수 있다).
function norm(p) {
  const r = path.resolve(p);
  return process.platform === 'win32' ? r.toLowerCase() : r;
}
assert.equal(norm(findDocRoot()), norm(path.join(inner, 'docs')));
```

### Analysis
- Root cause: findDocRoot의 init 전 폴백은 경로를 **계산만 하고 생성하지 않는다**. `fs.realpathSync.native`는 존재하지 않는 경로에서 ENOENT로 던지므로, 존재 검증을 전제로 한 real() 헬퍼(기존 테스트 파일의 Windows 경로 정규화 관례)를 그대로 쓰면 폴백 케이스에서 깨진다.
- Why it failed: 헬퍼의 암묵적 전제(비교 대상이 존재한다)가 새 테스트의 대상(존재하지 않을 수 있는 폴백 경로)과 충돌. 테스트 코드끼리 헬퍼를 공유할 때 전제가 함께 전파된다.
- How it was fixed: 존재하지 않을 수 있는 대상은 resolve+대소문자 정규화의 문자열 비교로. 존재 검증과 경로 동등성 검증은 다른 검증이다.

### Related Knowledge
- Patterns: [[ui-changes-need-browser-verification]] — "테스트는 파일 목록에 편입돼야 실행된다"는 전제까지 못박는 것의 가치(Case 2와 짝)
- **Anti-Patterns**: 공유 테스트 헬퍼의 암묵적 전제 무점검 재사용

## Case 4: 자동 마이그레이션이 done 명령 1발에 정본 레포 자신을 전환했다(도그푸드)

### Grounding
- Git Context: `hash:17d610d`
- Evidence: `git status --porcelain` 92개 rename 스테이징(R·RM), docs/kanban에서 계속되는 pick/done
- Confidence: 5/5

### Discovery
C2 마이그레이션 코드가 병합된 직후, 이 레포에서 칸반 done을 친 명령 한 발이 **정본 레포 자신의 doc/을 docs/로 전환**했다 — 별도 마이그레이션 절차 없이, 소비 레포와 동일한 경로로. 92개 항목이 rename(R·RM)으로 스테이징됐고 카드·클레임·activity.jsonl·raw·위키 모두 이동 후 정상 동작(이동 후 첫 done이 docs/kanban/done에 기록됨). 계획상 C6 카드가 예고했던 도그푸드가 자연 발화로 먼저 실측된 셈.

### Analysis
- Why non-obvious: 마이그레이션의 첫 실전 대상이 설계자 레포 자신이 될 줄은 예상 못함 — 커밋 직후 이 레포는 여전히 "레거시 doc/wiki만 있는 레포"였기 때문. 자기 도그푸딩 레포의 특권적 테스트 조건.
- Impact: 소비 레포 10곳이 0.6.0 이후 첫 명령에서 겪을 경험을 정확히 선견 — 보드 연속성·스테이징 상태·출력 문구 모두 실측. 잔여 리스크는 qmd 경로 썩음뿐이었고 그마저 안내 문구가 정확히 가리켰다.
- Action taken: 전환 순간 상태를 독립 커밋(17d610d)으로 봉인 — 이후 C3~C5 커밋에 rename이 섞이지 않게. qmd는 `qmd collection remove llm-wiki-wiki llm-wiki-wiki-raw` → `llm-wiki compile index`로 재등록·임베딩 갱신까지 완주, 시맨틱 검색이 docs/ 레이아웃에서 동작 실측.

### Related Knowledge
- Concepts: [[auto-update-copy-source]] — 같은 "npm update만 하면 된다" 자동 철학의 레이아웃 확장
- Patterns: [[kill-the-tree-not-the-wrapper]]

## Case 5: 쿼터 워치독은 3겹 구조 — 트리거만 ZCode 전용, 판정은 프롬프트(코드 0줄)

### Grounding
- Git Context: `hash:ff3e509`
- Evidence: skills/work-loop/SKILL.md 워치독 섹션(v12 부트스트랩·발사 프롬프트 템플릿), .zcode/overnight/TASK.md 사용 규칙, CronList 실측(빈 목록 — 09-24 해제 유지)
- Confidence: 5/5

### Discovery
"쿼터 워치독이 ZCode 한정 구현이 아니냐"는 사용자 질문의 분석 결과 — **절반만 맞다**:

1. **트리거(유일한 ZCode 전용 층)**: ZCode 자동화(CronCreate, `*/15 21-23,0-8 * * *`)가 발사 프롬프트를 새 세션으로 던진다. 워크스페이스 귀속이라 소비 레포 자가등록이 필요하고, work-loop v12 부트스트랩이 유일 전파 채널. "발사 성공 자체가 쿼터 생존 프로브"는 주기적 무인 모델 호출이 가능해서 나오는 트릭.
2. **판정·인계 로직(호스트 불문)**: lib/bin에 코드 **0줄** — 전부 발사 프롬프트 안의 절차(TASK.md status 판정 → stale 20분 → CLAIM+10분 관찰 → resume 지침 인계).
3. **제어 파일(호스트 불문)**: TASK.md(status 스위치+resume 지침)·heartbeat.txt는 평범한 텍스트 — `.zcode/` 위치만 ZCode 관례.

한정성은 설계가 명시적으로 인정한다: 부트스트랩이 "호스트에 예약 자동화 도구가 없으면 이 섹션 전체를 건너뛴다"고 게이트(우아한 퇴화). 코드로 만들지 않은 이유도 같은 원리 — 데몬은 plan.md 6.1 [확정] "서버는 필요 없다"에 걸린다.

### Analysis
- Why non-obvious: 구현체가 코드가 아니라 프롬프트+호스트 기능의 결합이라 "구현"의 위치가 파일시스템 어디에도 없다.
- Impact: 개선 방향이 명확해진다 — 트리거 층만 추상화하면 나머지 2겹은 그대로 재사용. 보드에 무소속 백로그 3장 등록: ① 워치독 트리거 호스트 추상화(crontab+헤드리스 CLI 등 동등 경로, 단 OS crontab은 발사 자체는 무조건 성공이라 "비용 0 실패 재시도" 프로브 의미의 재설계 필요) ② 워치독 자동 무장·해제(09-24 수동 해제의 절차화 + TASK.md의 옛 자동화 ID 잔재 정리) ③ compile index 선행이 compile list의 미승격 raw를 은폐(밤샘 커밋 절차에서 발화하는 갭).
- Action taken: 카드 3장 무소속 등록(인터럽트 규약 — 진행 중 마일스톤 'docs/ 전환'에는 미편성) + [[quota-watchdog]] 페이지 확장.
