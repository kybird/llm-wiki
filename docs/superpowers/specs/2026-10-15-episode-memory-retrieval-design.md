# 설계: 에피소드 메모리 — 고정 골격 + 회수 경로 우선 (2026-10-15)

- 상태: **승인("진행해보자") — 구현 진행**
- 토론 출처: 이 세션(문제점 슬롯 기각 → 상황/가설/판정/조치 확정, "회수 어휘가 병목"
  판정) + 직전 컨텍스트의 수렴 기록(harness memory episode-memory-refinement-intent).
- 근거: 카파시 LLM Wiki gist(헤더 라인=기계 계약, 본문 자유) · CoALA(회수·승격이
  기억 시스템의 실패 지점 — 필드를 고정할 자격 = 회수나 승격이 의존하는가) ·
  실증(2026-10-13 CUDA 사건이 이미 골격대로 쓰였다 / 이번 세션이 저장-성공·회수-실패
  표본: 완결된 설계를 메모리에서 회상하지 못하고 재유도).

## 1. Case 골격(고정) — docs/raw/YYYY-MM-DD.md

```
## [YYYY-MM-DD type] Case N: 제목        ← 헤더 라인 = 기계 계약(카파시)
                                          type: error|design|verification|discovery
### Grounding                             ← git hash · Evidence · Confidence
### 검색 단서                             ← 이 아래 설명(신규, 회수의 핵)
### 상황                                  ← 문제·갈림길·놀람·질문 전부. error 원문 그대로 규칙은 이 안
### 가설                                  ← 그때 뭐라고 생각했나(대안·기각 이력 포함)
### 판정                                  ← 실제로 참이었던 것(루트코즈·선택 근거·메커니즘 공통)
### 조치                                  ← 그래서 뭘 했나
### Related Knowledge                     ← 선택(그래프 간선 [[..]])
```

- 섹션 **본문은 자유 산문**. 기존 4타입 템플릿은 폐지 — 전부 이 골격의 인스턴스다
  (타입은 회수 필터용으로 헤더에만 산다). "문제점"은 error 사례에서 상황을 채우는
  관례로 스킬 가이드에만 잔존(스키마 아님 — "모든 에피소드가 문제"가 되는 비뚤림
  방지, 사용자 판정).
- 날짜가 헤더에 있는 이유: 인용될 때(위키 Grounding 등) Case가 자기 식별이 되게.

## 2. 검색 단서(신규 고정 필드)

> 기록은 "안 상태의 나"(교훈에 이름 붙인 어휘)가 쓰고, 검색은 "모르는 상태의 나"
> (증상·과제의 어휘)가 친다 — 이 간극이 구조적 어휘 갭이다(plan.md 5.1(3)).

Case를 쓰는 순간에만 존재하는 어휘 = "이 문제를 모르던 내가 검색창에 쳤을 단어".
에러 문자열 조각, 파일명, 명령어, 증상어. 작성 직후 증발하므로 쓰기 시점에 강제
남긴다. `aliases`(컴파일 시점 사후 수습)는 2차 안전망으로 내려간다.

## 3. 질의 로깅 + 환류 루프

- `llm-wiki search`가 모든 질의를 `docs/raw/search-queries.jsonl`에 append:
  `{ts, query, grep: N, semantic: N}` — 10k줄 상한(activity.jsonl과 같은 규율).
  compile/lint의 .md 필터와 간섭 없음(실측).
- `llm-wiki compile list`가 0결과 질의를 "단서·alias 후보"로 보고 → 승격 시점에
  환류. "에이전트가 뭘 치는 경향"이 추측에서 측정이 된다.

## 4. 읽기 훅 — work-loop pick 시 검색

pick 직후 `llm-wiki search "<카드 Goal 키워드> <건드릴 파일명>"` — 행위 직전
쿼리(세션 시작 의식만으론 부족하다는 이번 세션 실측)를 절차화. 스킬 프롬프트 수정.

## 5. 강제 — lint 골격 검사

wiki-lint가 docs/raw/*.md의 모든 Case에 대해 헤더 라인 형식과 6개 고정 섹션
존재를 검사(보드 이슈 섹션과 같은 패턴). **컷오프 2026-10-16**(이후 날짜 파일만
엄격) — 마이그레이션 카드가 레거시 15개 파일을 전환하며 컷오프를 제거한다.

## 6. 마이그레이션
