# 설계 제안: 무소속 마일스톤(영구) + 사후 편입

- 날짜: 2026-10-14
- 상태: **제안 — 사용자 판정 대기** (미승인. 승인 전에 구현 없음)
- 토론 출처: 이 세션 브레인스토밍(질문 2회 응답 + 3점 권장안 보류, 아래 "미결정 3점")
- 승인 후 정본: **plan.md 3.8 개정**. 이 문서는 토론 기록으로 남는다.

## 1. 배경과 문제

2026-09-21 규약은 인터럽트(사용자 요청·버그·follow-up)를 "무소속 todo 백로그"라는
제3의 상태로 착지시킨다. 사용자 판정: **떠 있는(무소속) 카드가 보기 싫다 — 모든
카드는 마일스톤에 종속되어야 한다.** 무소속은 "무소속 마일스톤"으로 묶되, 마일스톤은
각자의 종료 규칙을 가지므로 무소속 마일스톤은 **종결되지 않는다.** 대신 이미 종결된
카드들을 **사후에** 마일스톤으로 묶을 수 있는 경로를 만든다.

## 2. 모델 — 개념은 마일스톤 하나

| 요소 | 내용 |
|---|---|
| **무소속** | 예약 제목 `"무소속"`의 실제 마일스톤 카드. 모든 카드의 기본 소속. 종결 없음(§3). |
| **계획 마일스톤** | 기존 kanban-plan 흐름 그대로 — 태생 소속(`card new --milestone`), 봉인, 전원 종결 시 자동 종결. |
| **사후 편입(신규)** | 종결된 카드를 **활성 마일스톤(새 묶음 포함)**에 묶는 경로: "이 카드들은 사실 한 목적이었다"를 나중에 붙인다. 종결 마일스톤은 불변 — 주제 수정·누락 보강은 새 마일스톤(§4). |

## 3. 종료 규칙의 데이터화

마일스톤 프론트매터에 `conclusion` 필드를 추가한다(왕복 보존 대상).

- 생략 = `members` — 전원 종결 시 자동 종결(기존 동작, 무변)
- `never` — 자동 종결 스킵. **무소속 전용.**

무소속은 영구라 같은 제목 재생성 충돌(제목=식별자, 3.5 전역 유일)이 원천적으로
없다. `completeMilestoneIfAllTerminal`은 `conclusion: never`면 즉시 리턴.

## 4. 소속 규칙 매트릭스

| 카드 상태 | 대상 마일스톤 | 경로 | 가드 |
|---|---|---|---|
| 신규 | 지정 없음 | `card new` (플래그 생략) | **무소속 자동 부착**(§5) |
| 신규/활성 | 멤버 0 | `card new/edit --milestone` | 자유 — 계획 분해 중(기존) |
| 활성 | 멤버 ≥1(활성 멤버 유무 무관) | `card edit --milestone` + `--scope-amend` | 봉인 — **기존 코드 그대로, 무변** |
| 활성 | 종결 마일스톤 | — | 불가(썩은 상태 방지, 기존 무변) |
| **종결** | 활성 마일스톤(새 묶음 포함) | `card edit --milestone` + **`--retro "<사유>"`** | **신규 경로** — 봉인 미적용, 감사만(§6) |
| **종결** | 종결 마일스톤 | — | **불가 — 마일스톤 불변.** 주제 수정·누락 보강은 그 주제의 새 마일스톤을 만들어 `--retro`로 수집(§8-3) |
| 종결 | (활성 마일스톤에서 해제) | `--remove-milestone` + `--retro "<사유>"` | 오분류 정정 — 감사만. 종결 마일스톤에서의 해제도 불가(불변) |

**봉인은 손대지 않는다.** 초안에 있던 "활성 멤버 기준으로 봉인 정합화"는
자기 리뷰에서 취소: "전 멤버 종결 + review 대기도 결승선 확정"이라는 기존 판정과
충돌하고, 사후 편입(종결 카드)은 봉인을 안 거치는 별도 경로이므로 정합화가
불필요하다. 혼합 묶음(활성+종결) 조립 순서는 기준 문서로 해결한다(§8 — 활성 먼저).

단 한 가지 예외: 봉인은 `conclusion: never` 대상, 즉 **무소속에는 적용하지 않는다**.
봉인이 보호하는 건 결승선인데 무소속에는 결승선이 없다 — 주차장으로 옮기는 건
범위 변경이 아니다(자기 리뷰에서 발견: 이 예외가 없으면 마이그레이션과 무소속
환원이 매번 `--scope-amend` 소음을 낸다).

**종결 마일스톤은 재오픈하지 않는다(불변, 2026-10-14 토론).** 사후 편입으로
종결 마일스톤을 열어 멤버를 더하는 대신, 그 주제의 **새 마일스톤**을 만들어 종결
카드를 `--retro`로 모은다. 이유: (1) verdict(2026-10-11)가 확립한 "종결은 상태
불변, 이력은 append"와 같은 길 — 재오픈은 이 원칙을 깨는 두 번째 관례가 된다.
(2) done→활성→재종결은 milestone-done 활동·리포트 이중 집계 churn을 만든다.
(3) 회고 타임라인 정직성 — "X 계획은 그날 끝났다"가 영원히 참. 주제가 계속
진화하면 마일스톤의 연속(에포크)으로 기록되고 각자 자기 결승선을 가진다 —
소프트웨어의 지속적 변경은 새 마일스톤의 연속으로 남지, 옛 결승선의 소급
이동으로 남지 않는다.

### --remove-milestone (활성 카드)

해제 대신 **무소속 환원** — "소속 없는 카드 0장" 불변식 유지. 종결 카드의 해제는
오분류 정정이므로 `--retro` 사유를 요구한다(2026-09-18 교훈: 가드는 set/remove
쌍 경로에 모두).

## 5. 무소속 자동 생성·자동 부착

- `card new`가 `--milestone`을 받지 않으면: 살아있는(비종결) 제목 `"무소속"` 카드에
  태생 소속시킨다. 없으면 자동 생성한다 — `kind: milestone`, `conclusion: never`,
  Goal은 "인터럽트 기본 착지 — 목적 축 아님, 사후 편입 대기" 상수.
- kanban-plan은 실수 여지 없이 기존대로 마일스톤 먼저 생성 + 태생 소속이므로
  영향 없다.
- pick은 이미 마일스톤 카드를 거부한다(기존 가드) — 무소속이 작업 항목으로 집히는
  일은 없다.

## 6. 사후 편입 감사 (--retro)

범위 변경(`--scope-amend`)과 분리된 종결 카드 전용 사유 플래그. 이력 큐레이션이지
결승선 확장이 아니기 때문. 부수 효과:

- 카드 Notes: `- <ISO> — 사후 편입: 마일스톤 '<M>' — <사유>`
- activity: `action: 'retro-attach'`(해제는 `retro-detach`)
- 대상(활성) 마일스톤 Result에 편입 라인 append — 종결 시점의 멤버 수는 그때의
  기록이므로 소급 수정하지 않는다

## 7. 자동 종결 트리거

- 종결 사건(done/supersede/abandon) 뒤 체크: 기존 + `conclusion: never` 스킵.
- 사후 편입은 종결 체크를 **트리거하지 않는다** — 조립 중인 묶음을 첫 편입에
  종결시키는 경쟁을 막는다. 전원 종결 묶음은 조립자가 `card done "<M>"`으로
  완결한다(마일스톤 수동 종결은 이미 동작 — pick만 막혀 있고 done은 안 막힘,
  lib/kanban-cmd.js:772). 혼합 묶음은 마지막 활성 멤버의 종결 사건이 자동 종결.
- 조립 후 종결 망각(멤버 전원 종결인데 활성으로 방치)은 `llm-wiki lint`가
  지적한다 — 저장된 상태는 어느 밤 잊히고 썩는다(3.7 원칙 1).

## 8. 마일스톤 기준 (plan.md 3.8 개정안 골자)

1. **계획 마일스톤**: 분해가 2장 이상으로 갈라지면(기존 무변).
2. **무소속**: 인터럽트 기본 착지. 목적 축이 아니다 — 정산 대상 아님, 영구.
3. **사후 편입**: 무소속·종결 스트림에서 같은 목적의 카드를 발견하면(2장 이상
   권장) 묶어 마일스톤으로 승격 — 제목이 곧 그 목적의 이름. 묶음은 항상 **새
   마일스톤 또는 진행 중 마일스톤**(종결 마일스톤은 불변, §4). **조립 순서: 활성
   멤버를 먼저 붙이고(멤버 0이면 자유), 종결 멤버는 `--retro`로 그다음.**
4. 아침 의식 선택지 개정: "새 마일스톤 / 범위 변경 / abandon" → "사후 편입 /
   범위 변경 / **무소속 방치(합법 상태)**". 무소속 방치가 합법이 되므로
   "'나중에' 금지" 문장은 "사후 편입 후보를 발견하고도 미루는 것 금지"로 좁힌다.

## 9. 철학 충돌 4개의 수습

| 충돌(기존) | 수습 |
|---|---|
| 마일스톤 = 결승선 있는 목적 축 | 무소속은 목적 축이 아닌 **인테이크 버퍼**로 문서화 + 뷰·리포트에서 계획 마일스톤과 구분 |
| 전원 종결 자동 종결 | 종료 규칙을 프론트매터로 일반화(`never`) — 예외가 아니라 마일스톤 속성 |
| 소속 봉인(결승선 보호) | 봉인 무변. 사후 편입은 별도 경로(+감사)로 간다 |
| "종결 카드 소속은 이력" / 무소속=제3의 상태 | 무소속 상태는 데이터에서 제거(무소속 멤버십이 곧 인터럽트 표식). 이력 편집은 `--retro` 명시 사유 + 흔적으로 허용하되 대상은 **활성 마일스톤만** — 종결 마일스톤은 불변(§4) |

## 10. 뷰·리포트

- board/monitor 마일스톤 패널: `● 무소속 — N장 (영구)` — 완료율 대신 대기
  인터럽트 수.
- `board report`: 무소속은 마일스톤 통계에서 분리 집계 — "미정산 인터럽트 N장" 지표.
- 사후 편입 마일스톤은 일반 마일스톤과 동일 집계.

## 11. 마이그레이션(1회)과 테스트

- 현재 무소속 활성 4장(발산 방지 튜닝[review], 웹 뷰 — 드래그 이동, 쿼터 워치독
  트리거 호스트 추상화, 쿼터 워치독 자동 무장·해제)을 무소속에 부착하고 무소속
  카드를 생성한다. 부착은 봉인 예외(§4)로 자유롭다 — `--scope-amend` 소음 없음.
- 회귀(2026-09-18 쌍 경로 패턴): 편입/해제 set·remove 쌍, `never` 스킵, 자동
  생성 멱등, 활성 해제 무소속 환원, 종결 마일스톤에 활성 카드 편입 시도 거부,
  **종결 마일스톤에 종결 카드 편입 시도 거부(불변)**, **전원 종결 활성 마일스톤
  lint 지적**.
